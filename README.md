# Codex Standalone Linux

## v1.4.0：账户隔离与用量统计

- **同一个 Codex 后端，独立网页账户视图**：项目保存明确的 ownerId；即使另一个账户也是网页管理员，也不会在项目、文件或聊天接口里看到他人的项目。管理配置页仍属于可信管理员的管理权限，不是租户安全边界。无项目聊天按网页账户隔离，直接猜测任务 ID 或事件流地址也不能跨账户读取。
- 新项目固定前缀为服务用户主目录下的 `CodexProjects/<账户标识>/`，只输入文件夹名称。同名文件夹在不同账户下互不冲突。现有目录不搬移、不覆盖。旧项目只有一个授权用户时归该用户，其余未明确归属的旧项目归现有首个管理员；原只读授权保留。
- **输入框下方**显示轮数、步骤、LLM/工具耗时、首 token、生成速度、缓存命中和输入/输出 tokens。步骤是去重后的 Codex 用量事件，不是 HTTP 调用次数；耗时是本机观察值，无法取得的数据显示破折号。
- **右侧只保留累计美元折算额度和订阅周期百分比**；“使用统计”打开二级看板，提供时间/模型/供应商筛选、趋势图、模型汇总和分页日志。点日志进入三级计价快照。
- 费用/额度默认 **5 分钟**刷新，可改 **30 分钟**；隐藏页面停止轮询。所有网页账户共用一次 5 分钟额度采样，服务端复用汇总缓存；历史用量增量写入 SQLite 日汇总，不定期重扫 Codex 聊天文件。图表仅打开明细时生成，不增加图表框架依赖。

### 定价与周期口径

默认价格核验日为 **2026-09-09**，来源为 OpenAI 官方费率表：
https://help.openai.com/en/articles/20001415-chatgpt-rate-card-enterprise-token-based-pricing

- Sol 按用户要求使用**非促销价 $5 / $0.50 / $30**（普通输入 / 缓存读取 / 输出，每百万 tokens）。不使用当前促销价。
- Astra 在 Codex 中不收长上下文倍率；适用的 GPT-5.4、GPT-5.5、GPT-5.6 系列超过 272K 输入时，输入及缓存读取 2×，输出 1.5×。GPT-5.4 Mini 不套用并未确认的该规则。
- 后端明确回传 fast/priority 档位时应用快速模式倍率：GPT-5.4 为 2×，其余已配置的快速模式为 2.5×。未回传的档位不能被可靠识别，按标准档折算并在记录中标记。
- 官方 Codex 口径**不加收缓存写入费**，与 API 的 GPT-5.6 及后续模型缓存写入价不同。缓存命中输入只按读取价计一次；输出已含 reasoning，不重复相加。
- 未知模型、研究预览模型不猜别名、不按零价计费；长上下文/快速倍率及每条记录使用的价格快照可审计。管理员在“定价与周期”编辑单价和真实订阅起止日，价格更新只影响后续记录。
- 所有美元数字均为 **API 价折算估计**，不是订阅扣款账单，更不是第三方供应商的实际发票。新统计从启用并绑定后开始；现有聊天的第一次累计快照只作为基线，不把旧聊天历史重复收费。

设同一观测区间内全部已定价费用为 C，官方周额度累计增量为 P（百分数），本账户费用为 Ci：

`一周总美元额度 ≈ C ÷ (P / 100)`

`本账户累计周用量百分比 ≈ Ci ÷ C × P`

`本账户订阅周期百分比 ≈ 本账户累计周用量百分比 ÷ 5`

`一个周期总美元额度 ≈ 一周总美元额度 × 5`

不能把全历史费用除以单个当前周的百分比。程序保留跨周/重置卡的已观测增量，首次采样前的消耗不补算；零分母、多个不明确的周额度池或未定价用量不产生虚假百分比。后端若还有未绑定网页账户的桌面消耗，该比例只能是估算，不是官方账户分账。实际续费日期无法从周重置日期推出，新周期请更新统计起止日；不删除旧日志。

`usage.sqlite` 及其 WAL 保存在 WebUI 私有数据目录内，仅含账户/任务 ID、模型、tokens、时间与价格，不保存消息正文、工具参数或认证凭据。项目根目录仍不得包含该私有目录。


独立的 Linux Codex 工作台：**独立账号、独立 WebUI、独立端口（默认 3210）**。无需 ElementsPanel、数据库、前端构建或开发服务器。

> 不是 OpenAI 官方应用。生产程序只附加到已有 Codex 的 Unix socket / WebSocket，不启动、复制或重启 Codex。共享桌面任务的前提是桌面实例确实暴露了兼容接口；不能把任意新开的 app-server 当成桌面共享实例。

## v1.3：项目、无项目对话与桌面功能

- 项目选择同步当前桌面本地项目；管理员可填写服务器绝对目录新建项目，或使用已有目录。不覆盖已有文件、不自动初始化 Git。
- 无项目对话单独显示，不绑定当前项目。桌面使用 Codex 的独立聊天目录；普通 app-server 使用 WebUI 数据目录旁的独立 chats 目录，不开放该目录的文件浏览。
- 技能和插件读取当前目录的真实 skills/list、plugin/installed；网页只提交经校验的条目 ID，服务端转换为 skill / mention 结构化输入。新桌面聊天首条消息也可选择技能、插件、模型、强度、模式和权限。
- / 菜单提供 MCP、代码审查、侧边聊天、创建分支、压缩、反馈、归档、新聊天、状态、目标、置顶、计划模式、重命名。按用户要求不包含虚拟宠物。
- 侧边聊天是临时 fork，保留上下文，可返回原聊天；聊天分支目前在当前目录创建，不创建新 worktree。代码审查支持未提交更改或基准分支，使用 inline review，不创建审查子代理。
- 压缩、审查、反馈、归档、分支等操作须用户确认。反馈不包含额外日志。持续目标会交给 Codex 继续执行；这些操作不在自动化回归中对真实账号执行。
- 桌面新建使用已有桌面后端 thread/start（user 来源）和一次 turn/start，不附加代理委派提示，不使用 create_thread 工具来发送首条消息。没有视图 owner 的旧任务通过同一桌面的 thread/resume + 有界事件流接入。

### 桌面完整桥接

在 scripts/desktop-session.ts 启动时，若桌面已经提供 CODEX_DESKTOP_CDP_PORT，可附加其仅本机调试端点以调用现有 electronBridge。程序不会启动 Codex、打开调试端口、读取令牌或改变供应商。原有当前任务仍使用 owner 校验 IPC；其他任务使用同一后端，不另起 Codex。

**该端点拥有桌面控制能力，必须保持本机可访问，绝不能公开到网络。** WebUI 不开放任意 CDP、JavaScript 或 host 路由，只暴露经过权限、CSRF、目录和参数检查的功能接口。桌面版本改变时内部接口可能失效，失败不会伪装成功。

没有该端点时，保留旧版有限 IPC / 已有 app-server 能力，不声称桌面功能全部可用。普通 Linux app-server 模式也提供项目添加、无项目聊天及上述聊天操作；具体方法支持依赖现有 Codex 版本。桌面项目创建是添加到 Codex；普通 app-server 项目添加是 WebUI 授权目录，不能伪称修改了另一台桌面的项目。

边界：桌面新聊天首条消息暂不接受文件附件，已有项目任务可继续添加。无项目对话不开放项目文件上传 / 浏览。新 worktree 分支和桌面审批回复未在本版接入。额度和重置卡仅展示后端实际返回的数据；当前第三方供应商可能无法返回额度，不能推算或伪造。

## v1.2 历史版本：桌面新建任务

桌面任务管理接口可用且当前目录已保存为桌面项目时，管理员可以从网页新建任务：

1. 点击“新建任务”，确认显示的当前项目目录。此模式直接使用该目录，不会偷偷创建 worktree。
2. 输入首条文本消息，可选择模型和强度；不改模型时使用桌面的新任务默认设置。
3. 点击发送后，由已运行的桌面 Codex 创建任务并接收首条消息，网页切换至新任务、同步输出。不再调用一次 messages 接口重复发送。
4. 左侧列表可切回原任务；本标签页刷新时保留所选任务。

创建记录先落盘，再发起一次桌面操作。超时只读检查状态，不自动重复创建。已创建但首条消息未开始时，保留草稿并显示原因；结果未知时请用“检查创建状态”及桌面任务列表核实，不要直接再建同样的任务。

当前边界：桌面模式首条消息仅支持文本；权限和执行模式用桌面新任务设置，创建后可通过原发送界面调整、添加附件。相同目录已有运行中的任务时拒绝并发写入。不会自动创建 Codex 进程，不修改桌面认证，不调用模型子代理。

本机桌面管理适配器使用桌面提供的 CODEX_APP_TOOLS_PIPE_PATH（仅作本地端点，不从进程或配置中抓取）。若桌面未提供该端点或不开放相应工具，则继续使用单任务附加模式，不能伪装成支持新建。

## v1.1 历史版本：任务与模型同步

- 修复 HTTP 环境缺少 crypto.randomUUID 时不能发送、控件锁死的问题；空项目首次发送自动创建任务。
- 输入 / 选择基础功能、技能与已安装插件；附件、项目文件引用、访问权限。技能 / 插件使用后端验证过的结构化输入，不拼接不可信路径。
- 无管理接口时固定附加到已有任务；有管理接口时支持显式新建和切换同目录任务。重新选择当前任务不清空草稿。
- 桌面模型列表优先读取 config.toml 指定的 model_catalog_json，未配置时才使用模型缓存。监听配置和目录文件的变化，网页重新获得焦点时也会刷新；不定时轮询。
- 当前模型、推理强度、权限及协作模式来自桌面任务快照 / 状态流。默认继承桌面设置；仅用户主动修改的项在下一次发送时覆盖，可点击“跟随桌面”取消本地更改。
- 桌面内部 IPC 是实验性附加适配器，不等同于官方稳定的 app-server 协议。现有任务设置与本机配置目录是不同的数据源；如果配置已改变但桌面尚未应用，目录读取不保证模型能成功调用。

| 功能 | 常规 app-server | 当前桌面 IPC 附加 |
|---|---|---|
| 任务 / 输出 / 发送 / 停止 | 支持 | 初始任务 + 经验证的同目录任务 |
| 新建任务 | 支持 | 管理员；桌面提供管理接口且项目已保存；首条文本发送时创建 |
| 模型列表 / 推理强度 | 由 Codex 返回 | 配置目录 + 当前任务状态；变更通知刷新 |
| /、附件、项目引用、访问权限 | 支持 | 支持已开放的基础功能 |
| 技能与插件目录、MCP、目标写入 | 后端提供对应接口时支持 | v1.3 完整桥接支持；有限 IPC 不支持 |
| 额度窗口、重置卡 | 后端提供且账号允许时支持 | 请在桌面查看 / 操作，不伪造数值 |
| 审批答复 | 支持相应协议 | 在桌面处理 |

本机手动验证入口：显式设置 CODEX_DESKTOP_THREAD_ID 为已有桌面任务 ID、CODEX_DESKTOP_WEBUI_DATA 为独立数据目录，然后运行 node --import tsx scripts/desktop-session.ts。只监听 127.0.0.1:3210，不启动 Codex、不抓取认证信息、不自动发送消息。首次创建独立测试账号时，密码仅输出在本机终端，请妥善保管。

## 带宽与内存设计

| 项目 | 行为 / 上限 |
|---|---|
| 前端依赖 | 原生 HTML / CSS / JS；无 CDN、字体下载、框架运行时、屏幕视频流 |
| 静态资源 | 启动时预压缩 Brotli / gzip，ETag / 304；非首页缓存 1 小时 |
| 动态 JSON | 大于等于 1 KiB 才 gzip；无共享缓存 |
| 实时输出 | SSE，约 100 ms 合并一次增量；浏览器约 80 ms 合并 DOM 更新 |
| 断线恢复 | 游标重放；窗口过期才重新读取快照；重连指数退避，不重发写入命令 |
| 后台标签页 | 隐藏 15 秒后暂停 SSE，返回后续传；不定时刷新文件 / Diff / 额度 |
| 事件保留 | 最多 2048 条 / 4 MiB（先达到者） |
| 文本快照 | 最多 200 项 / 512 KiB 字符；单项 64 KiB 字符 |
| 慢客户端 | 每条流 64 KiB 高水位，积压时断开，靠游标恢复 |
| 长连接 | 每用户最多 6 条、全局最多 100 条；20 秒心跳 / 权限重验；10 分钟换新流 |
| 文件 | 上传 4 MiB / 下载 8 MiB；目录最多 500 项；Diff 256 KiB |

快照的 KiB 字符界限按 JS UTF-16 长度计算，不等同于网络字节数；SSE 缓冲和资源体积按实际字节计算。

## 快速运行（Linux，Node.js 22.14+ / 24）

```bash
# 克隆本仓库到新的独立目录，不需要原项目源码。
git clone https://github.com/1138069580qq-create/Codex-Standalone-Linux.git
cd Codex-Standalone-Linux
npm ci --omit=dev --ignore-scripts

# 用读取隐藏输入的方式创建本应用管理员。不要把真实密码写进 shell 命令历史。
read -r -s -p 'WebUI admin password (12+ chars): ' PASSWORD; printf '\n'
printf '%s' "$PASSWORD" | npm run user:add -- --username admin --admin
unset PASSWORD

# 直接运行生产程序，不执行 build，不启动 dev server。
npm start
```

默认监听 `127.0.0.1:3210`。远程访问推荐 HTTPS 反向代理；临时访问可用 SSH 隧道：

```bash
ssh -N -L 3210:127.0.0.1:3210 linux-user@your-server
```

在本机访问 `http://127.0.0.1:3210`。登录后：

1. **设置 → 扫描已有接口**，选择已验证的 Codex Unix socket 或 WebSocket；也可直接填入已有地址。
2. 在设置里创建普通账号，复制账号 ID。
3. 添加项目 JSON（目录须已存在），按需设置 grants。完整例子见 `config.example.json`。
4. 保存配置，点击 **连接 Codex**。连接不是启动 Codex。
5. 选择项目 → 选择 / 新建任务；模型列表来自真实 Codex。

如果扫描没有结果，程序会保持未连接。它不会读取 `~/.codex/auth.json` 来绕过没有共享接口的问题，也不会自动运行 `codex app-server`。

## 配置

| 环境变量 | 默认 / 说明 |
|---|---|
| `CODEX_WEBUI_HOST` | `127.0.0.1` |
| `CODEX_WEBUI_PORT` | `3210`，避免与原面板端口冲突 |
| `CODEX_WEBUI_ORIGIN` | 本地监听 origin；反代必须设置如 `https://codex.example.com`，无末尾斜杠 / 路径 |
| `CODEX_WEBUI_DATA` | `~/.local/share/codex-webui`；保存 users / config / receipts / usage.sqlite，目录应只允许服务用户访问 |
| `CODEX_WEBUI_PASSWORD` | 仅 CLI 创建 / 修改账号时读取；建议用 stdin 代替环境变量 |

非回环监听必须显式设置 HTTPS origin。WebUI 自身不处理 TLS，必须部署对应的 HTTPS 反代，**不要把 HTTP 后端直接公开到互联网**。程序不信任任意 `X-Forwarded-*`；来源以配置为准。反代后的登录速率限制按直连反代地址聚合，Nginx 可再做客户端 IP 限流。

`users.json` / `config.json` / `receipts.json` 使用原子写入与 `0600` 文件权限，父目录 `0700`。会话保存在内存里：重启需要重新登录，最长 12 小时、30 分钟无请求失效。活动 SSE 的权限检查算活动。修改账号使旧会话立即失效。

通过网页修改账号实时生效；通过 CLI 修改运行中的账号数据库后，需重启 WebUI。当前版本通过调整账号角色和移除项目 grants 撤销项目访问，不提供网页删除账号功能。

## 授权与边界

- `view`：项目任务 / 输出。
- `send`：创建、发送、停止任务和回答问题。
- `approve`：允许 / 拒绝命令和文件审批。
- `files`：文件列表、上传、下载、Diff、附件。
- 后三项必须同时具有 `view`。管理员有配置管理权限；日常项目接口仍检查明确的 ownerId，不绕过账户隔离。
- 同一项目同一时间只允许一个任务写入；不同项目可在总并发限制内运行。建议独立 Git worktree。
- **这不是 OS 多租户沙箱。** 多个 WebUI 用户共用同一 Linux 用户、同一 Codex 身份及额度。不要向互不信任的人授予 `send` / `approve`，尤其不要批准越权命令。需要强隔离时使用独立 Linux 用户 / VM / 容器及独立 Codex。
- 其他客户端启动的任务状态会尽可能查询，但跨客户端的项目互斥并非原子分布式锁。
- 不提供密码找回、SSO、MFA 或公网注册；若需要公网使用，建议 VPN / 额外身份认证网关。

## 部署与测试

- `docs/DEPLOYMENT.zh-CN.md`：systemd 用户服务、Nginx、容器与升级流程。
- `docs/TEST-REPORT.zh-CN.md`：本次实际测试结果与未验证事项。

```bash
npm ci --ignore-scripts
npm run check           # tsc --noEmit + JS 语法；不是 build
npm test                # 单元 / 回归 / HTTP 测试：部分使用协议测试桩

# 只读连接已有真实 Codex；不会启动进程、创建任务或调用模型
CODEX_EXISTING_ENDPOINT=/run/user/1000/codex/app-server.sock npm run test:live

# 显式允许测试专用的隔离 Codex 进程（不使用真实登录凭据、不调用模型）
CODEX_TEST_BINARY=/absolute/path/to/codex CODEX_TEST_ISOLATED=1 npm run test:real
```

测试保留临时目录以便审计，不递归删除。无对应环境变量的真实测试会跳过，不得把跳过当成通过。

## 目录与许可

`src/backend/` 是复制到独立仓库的 Apache-2.0 插件协议核心；`src/auth.ts`、`src/server.ts`、`src/routes.ts` 等是独立服务层；`public/` 是无需构建的全新界面。所有路径均在本仓库内，没有指向原项目的源码依赖。
